- **저장 스펙 연결:** 193명 중 160명은 검산용 레벨 400에서 스탯 합계·단일 히트 입력 생성 성공. 28명은 SSR 기준 표를 적용할 수 없는 등급/메타데이터, 5명은 고정된 legacy 역할 자료 부재로 미완료 표시. 193명 모두 전투 지원을 선언하는 것이 아니다.
- **히트 비교:** 기존 C# 테스트에 기록된 실측 18점을 재사용했다. 최종 반올림 경로는 고정 upstream Python `calc_damage` 실행 결과와 18점 모두 같았다. 크리 확률을 0 또는 1로 고정한 결정적 조건이며 난수 표본을 만든 것이 아니다. 같은 인자·연산 순서를 사용한 Python 반올림 대조는 합성 경계 30점을 포함해 48점 통과했다.
- **실측 잔차:** C# 항별 내림 0~+52, 최종 반올림 0~+57, 단계별 내림 0~+52. 허용오차로 이 차이를 숨기거나 특정 후보의 실게임 정확성을 확정하지 않았다. 원천 표시 계수의 정밀도와 조건 확인이 추가로 필요하다.

## 입력 매핑에서 보존·수정한 사항

기초 스탯 연산 순서는 기존 C#을 그대로 유지했다. 큐브/소장품의 상시 HP·DEF 비율은 기존 조립 순서에 적용하며 OL은 같은 값끼리 묶어 증가분을 반올림한다. DEF 등 중간 실수가 나오더라도 표시값을 맞추기 위한 추가 반올림을 임의로 삽입하지 않는다.

소장품은 기존 등급 없는 1-based 표를 그대로 API 레벨에 연결하지 않았다. upstream `collection.json`의 R0~R15/SR0~SR15를 사용하며 SSR 애장품은 해당 원천 매핑대로 SR15 기초 스탯과 공통 효과를 사용한다. 애장품의 캐릭터 스킬 교체는 P03 대상이다. 원천 API 레벨/등급은 변경하지 않는다. 이 매핑 보정은 C# 기초 스탯 연산 변경과 구분한다.

큐브는 정확한 종류·레벨이 없으면 미완료로 처리하며 15레벨로 보충하지 않는다. 조건부 효과는 상시 효과로 계산하지 않고 보류 목록에 남긴다. 기본 스킬·버스트·팀 버프도 자동 적용하지 않는다.

OL은 P01의 정규화된 비율을 그대로 사용한다. Integer 저장 방식인 크리·크리 대미지·차지 대미지도 다시 /10000하지 않는다. `IncHurtDef`는 P01의 방어력 옵션 매핑을 따르며, `StatAccuracyCircle`·장탄·차속·크리 확률 등 단일 히트에 직접 소비하지 않는 항목은 P03 무기/RNG 대상으로 표시한다.

## 정수화 계약과 한계

- `legacy_term_floor`: P = (ATK − 유효 DEF) × W × C; B2 = floor(P) + 각 활성 보너스 floor(P × bonus); 마지막 B3×B4×B5 곱 후 floor.
- `final_round_even`: 동일 입력·의미 배율에서 중간 정수화 없이 마지막 반올림. 정확히 절반이면 짝수로 반올림하며 최소 1. **upstream의 다른 스탯 계산법까지 채택한다는 의미는 아니다.**
- `nested_floor`: 항별 B2 이후 B3/B4/B5 단계마다 floor하는 추가 가설.
- ATK ≤ 유효 DEF는 각 후보의 공통 비교 조건으로 최종 1. 작은 양수 타격은 legacy 후보가 0, 최종 반올림 후보가 1이 될 수 있어 차이를 보존한다.
- 수치형은 기존 C#과 같은 binary64. 입력한 십진 값과 CPU의 표현/연산 순서 차이도 경계에서 영향을 줄 수 있다. decimal이나 float32를 게임 내부 형식으로 확정하지 않았다.
- 타격 유형을 바꾸면 해당 스킬 계수·공격력 기준·크리/코어/차지 허용 조건도 실제 효과에 맞게 입력해야 한다. UI가 캐릭터 스킬을 자동 해석하지 않는다. SG 펠릿 분할·부분 차지 보간·발수·스킬 타이밍은 P03 검증 대상이다.
- 실게임 스탯 화면을 이번에 새로 대조하지 않았으며 과거 실측 기록의 완전한 재현 조건도 새로 관측하지 않았다.

## 추후 실측을 받는 방법

UI에서 캐릭터·적용 레벨·적 방어력·적용 공격력·계수·차지/크리/코어/거리/풀버스트·버프를 맞춘 뒤 실측 대미지를 입력한다. 측정 대상·시간·스킬·버프를 메모하고 JSON을 저장하면 입력, 수동 변경 필드, 스냅샷/계산 자료/규칙 버전, 후보별 차이를 함께 남길 수 있다. 사용자에게 CSV 작성을 요구하지 않는다.

서로 다른 조건을 섞은 총딜 하나로 정수화를 선택하지 않는다. 먼저 같은 조건의 비크리·크리·코어 등 단일 히트 관측을 비교하고, 후보가 실제로 갈리는 조건을 고른다. 불명확한 입력을 임의 보정 계수로 맞추지 않는다.

## 데이터팩·클라이언트 제한 조사

기존 프로젝트의 ConfigBattleTable, 디코딩된 FunctionTable·CharacterSkillTable 키와 현재 설치 경로의 sd.bin ZIP 내부 ConfigBattle을 읽기 전용으로 확인했다. 전투 상수 및 계수/효과 필드는 있으나, 확인 범위에서 round/floor/ceil/trunc에 해당하는 키나 정수화 실행 순서를 찾지 못했다. 이 결과는 클라이언트 전체에 정보가 없다는 증거가 아니다.

전역 core 관련 상수와 캐릭터 무기별 core 계수는 값이 달라 적용 지점 확인 없이 교체하지 않았다. 실행 파일 분석·게임 프로세스 접근·후킹·새 데이터팩 수집은 수행하지 않았다. 추출값·파일 hash·조사 범위는 Git 제외 `artifacts/p02/data-probe.json`에만 남긴다.
