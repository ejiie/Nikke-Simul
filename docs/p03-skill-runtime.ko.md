# P03 — 5인 스킬 효과 실행

2026-09-08. 사용자 요청의 **1번: 리타·블랑·누아르·앨리스·모더니아 스킬 실행** 구현 기록이다. 공식 체인의 효과를 평타 시간축에 연결하고 API로 실행·저장한다. **실게임 실측 검증 전이며, P03 전체 완료나 실제 팀 게이지 기반 전투 완료를 뜻하지 않는다.**

## 실행 범위

| 캐릭터 | 연결한 처리 | 다음 단계에서 소비/검증할 부분 |
|---|---|---|

회복은 내부 HP를 실제로 바꾸므로 누아르/앨리스의 조건도 재평가한다. 보스 피격 AI 대신 `initialHpRatios`, `hpObservations`로 관측 HP를 지정할 수 있다. 사망 상태는 아직 입력받지 않는다. 명중률 버프는 모더니아의 공증 발동 조건에 사용하며, 현재 모든 펠릿이 명중하는 조건을 명중 확률 모델로 오인하지 않는다.

`GET /api/runtime/catalog`의 `allLevelsExecutable`은 **공식 체인에 현재 해석하지 못하는 원자/메타데이터가 없는지**를 뜻한다. 실게임 정확성, 생존·보스 기믹까지의 완전 지원 표시는 아니다. 5명 × 3슬롯 × 10레벨을 사전 검사한다. 모르는 함수·조건·phase·body는 진단하고 해당 실행을 거부해 부분 결과가 정상 결과로 저장되지 않게 한다.

## 수치·상태 계약

- 계정 `skills["1"/"2"/"3"]`을 `skill1/skill2/burst`로 매핑하며 실제 레벨을 그대로 쓴다. 누락 레벨을 10으로 채우지 않는다. 애장품 스킬 교체가 있는 입력은 현재 거부한다.
- 스탯 원값과 기존 OL 합산 순서를 유지한다. 자기/수혜자 기준 공증은 원래 `StatAttack`에 대한 비율 목록에 합류한다. **다른 시전자의 공격력에 비례한 공증**은 시전자 원값에서 계산·반올림한 고정 증가량으로 보존해 수혜자 비율 버프 뒤에 더한다. 다시 수혜자 공증으로 증폭하지 않는다.
- 누아르 설명은 시전자 ATK, 블랑 회복·보호막 설명은 시전자의 **최종 최대 HP**다. 누아르 타인 공증은 native caster 기준, 회복·보호막은 적용 시점의 최종 최대 HP 스냅샷을 사용한다. 캡처 시점은 실측 검증 대상으로 남긴다.
- `StatChargeDamage`, `StatCriticalDamage`는 이 그래프에서 `Integer`라 해도 `/10000` 비율 단위다. `StatAmmo(Integer)`는 탄 수, `ChangeCoolTimeUlti(Integer)`는 1/100초, `UseCharacterSkillId(Integer)`는 ID다. `ValueType`만으로 모든 효과를 일괄 변환하지 않는다.
- 차지 대미지 = 기본 × (1 + 배율 증가분) + 가산. 스킬 차지 가산은 이 마지막 축에 넣는다. 타인의 차지시간을 기준으로 한 차속은 시전자 원래 시간에서 계산한 1/100초 단축량을 수혜자에게 적용한다.
- 소장품 등의 일반 공격 계수 증가는 교체 무기 평타에도 한 번 적용하며, 직접 스킬/추가타 계수에는 적용하지 않는다. 기존 `BasicHit.Coefficient`에 이미 포함된 증가량을 기본 평타에 중복 적용하지 않는다.
- 시간 버프를 적용/해제할 때 발사 모델을 재생성하지 않는다. 현재 탄·차지 진행·연사 누적·재장전 진행을 유지한다. 최대 장탄 감소 시 현재 탄을 상한으로 제한하고, 탄 회복은 변경된 최대 장탄을 사용한다. 이 변경 시점/클램프 정책은 실측 비교 대상이다.
- 쿨다운은 1/300초 정수 단위로 마감 시각을 보존한다(1프레임=5, 1/100초=3). 여러 쿨감의 1/100초 정밀도를 유지한 뒤, 도달 가능한 다음 프레임에서 시전을 허용한다. 매 쿨감마다 프레임으로 반올림해 누적 오차를 만들지 않는다.
- 스킬 직접 피해는 차지·코어·적정거리 보너스를 받지 않고 크리는 별도로 판정하는 초기 정책이다. 평타·교체 무기 평타는 무기 조건을 사용한다. 추가타를 평타 명중으로 다시 발행하지 않는다. 이 크리/판정 정책도 실측 전 확정으로 표시하지 않는다.
- 실험은 `roundingPolicy` 하나를 명시한다. 회복으로 HP 조건이 달라질 수 있으므로, 서로 다른 정수화 후보가 전투 상태를 공유하지 않는다.
- 최저 HP 대상의 비율/절대값 해석은 `lowestHpTargetBasis`로 비교한다. 초기값 `ratio`는 고정 upstream의 `_lowest_hp` 구현에 따른 후보이며 실게임 확정이 아니다. 엄폐는 `lowestCoverTargetBasis`의 초기값 `absolute`를 쓰며 역시 `ratio`와 비교 가능하다. 동률이면 편성 순서를 유지한다. 블랑의 실제 버프 수혜자를 관측해 선택할 규칙이다.

## 순서와 원인 기록

프레임마다 회복 주기 tick → 만료 → 관측 HP → 조건 갱신 → 풀버스트 종료 → 주기 스킬/지정 시전 → 지정 풀버스트 진입 → 발사/탄 소비 → 평타 피해/명중 트리거를 처리한다. 5초 지속 회복은 1초 간격으로 마지막 경계 tick까지 5회 처리한다. 같은 프레임 세부 순서와 HP 70%/80%의 정확한 경계 포함 여부는 실측 전 정책이다.

CharacterSkill은 `before_use → before_hurt → body → after_hurt → after_use`로 실행한다. phase 자체를 합쳐 없애지 않는다. 현재는 즉시 스킬의 동기 실행 정책이며, 실제 시전/명중 지연과의 대조는 후속 작업이다. 각 단계의 함수/하위 스킬/직접 피해에 부모 이벤트 ID를 남긴다. 연결 함수를 수혜자 수만큼 중복 실행하지 않는다.

리타의 `OnSkillUse` 값은 사용 횟수가 아닌 **스킬 그룹 ID**다. 원천의 상위 단계부터 배치된 함수 순서를 유지한다. 앞선 시전에 남긴 마커를 사용하므로 1회 시전으로 3단계가 한꺼번에 열리지 않는다. 누적 쿨감의 원천값은 2.34초 → 2.34+2.70초 → 2.34+2.70+3.17초다.

`full_burst_duration_request`는 모더니아의 15초 등 원천 지속시간을 P04에 전달할 계약이다. 현재 풀버스트 구간은 관측용 지정 입력이며, 버스트 시전만으로 자동 풀버스트에 진입하지 않는다. 실제 버스트 단계·게이지 검증은 P04에서 붙인다.

## API·저장

- `POST /api/runtime/skill-replays`: 기존 `X-Nikke-Token` 필요. snapshotId, characterIds, scenarioLevel, conditions를 받는다.
- `GET /api/runtime/skill-replays/{id}`: 저장 결과 재조회.
- 조건: `conditions.combat`은 기존 평타 조건, `conditions.roundingPolicy`는 필수 정수화 후보, `conditions.casts`는 `{frame, characterId, slot:"burst"}` 목록.
- HP는 `initialHpRatios`, `hpObservations`. 엄폐를 비교하려면 **팀 전원**의 `initialCovers: {characterId: {maxHp, currentHp}}`를 지정한다. 일부만 알려진 엄폐 HP로 절대 HP 순위를 만들어내지 않는다.
- SG 포함 시 기존처럼 `pelletCoefficientPolicy`를 필수 지정한다. 방어력은 이번 작업에서도 실행당 고정값이다. 20억 전/후 전환은 별도 작업이다.
- `data/local/skill-replays/`에 스냅샷/계산자료/공식 체인/규칙 버전, 실제 레벨, 입력 멤버, 효과별 결과·시전/버프/대미지 추적·잔여 상태를 원자적으로 저장한다. 개인 데이터는 Git에서 제외한다.
- 기존 `/weapon-replays`는 평타 전용 비교 경로로 유지한다. 새 스킬 실행을 기존 평타 결과로 덮어쓰지 않는다. UI 연결은 다음 작업이며 기존 최종 HP·ATK·DEF 표시를 유지한다.

히트 규칙은 `p02.3`이다. `AttackFlatBuffs`가 추가되었으며 빈 목록에서는 기존 결과와 동일하다. 입력 schema 2와 기존 필드는 호환된다. 스탯 규칙 `native-stat-shared-buffs-v2`와 원본 `OverloadProcessor`는 유지한다.

## 검증

- 최종 회귀 **C# 99개(Core/Engine 62 + 입력/저장 37), Python 11개** 통과. Release 빌드 경고·오류 0, 잠금 복원과 P00/P02/P03 원문 hash 검사 통과. 기존 P02 160명 × 4버프 조합 **640건**, 히트 정수화 비교 **48건**, 기존 평타 API 검사도 재통과했다.
- 합성 회귀: 시전자/수혜자 공증, OL 보존, HP 경계 전환, 단계 마커 반복, 연결 함수의 대상 중복 방지, 추가타 재귀 방지, 중첩 상한, 디버프 만료, 쿨감, 무제한탄·무기 복귀, 장탄 적용 직후 상태, 차지 진행 유지, 보호막 만료, 엄폐 선택, trace 불변성.
- 공식 자료: 5인 150개 슬롯/레벨 정의 및 연결 그래프 사전 검사.
- 실제 저장 스펙: `tools/data-pipeline/audit_p03_skills.py`로 180초 지정 시전 실행, 3개 정수화 후보 분리, 구성원/effect/팀 합계, 저장 후 재조회, 상세/요약 동일성, 잘못된 쿨다운·미지정 정수화 거부 확인.
- 위 실행은 **관측 조건을 합성한 개발 검산**이다. 실제 게임 대미지를 측정하거나 오차 0으로 검증한 결과가 아니다. 실측 수신 후 [측정 안내](p03-measurement-guide.ko.md)의 조건으로 대조한다.
