# 사용자 요구 사항 목록 — 2026-09-29~

배포본(2026-09-29, [배포 기록](desktop-release-original-2026-09-29.ko.md))을 사용하며 사용자가 하나씩 작성하는 요구 사항을 받은 그대로 기록한다. 항목마다 상태(접수 → 배정 → 구현 → 검수 → 배포)를 갱신한다. 배정은 요구가 모이면 묶어서 한다(사용자가 즉시 배정을 원하면 바로).

## 공통 참고

- **참조 프로젝트:** 사용자가 진행 중인 다른 프로젝트 [ejiie/Nikke-Local-Lab](https://github.com/ejiie/Nikke-Local-Lab). **UI와 통계 쪽을 참조한다**(사용자, 2026-09-29). 현재 desktop UI도 원래 Nikke-Local-Lab 화면에서 이식했다([이식 기록](desktop-ui-migration.ko.md)). 로컬에는 `C:/Users/user/Documents/GitHub/Nikke-Local-Lab.zip`만 있고 clone은 없다 — 참조 시 원격 저장소를 읽기 전용으로 사용하고, 코드를 복사할 때는 출처를 기록한다.
- 이미 있는 이미지 자원: `data/local/presentation/assets/ui/`의 `code-{fire,water,wind,iron,electric}.png`(속성), `weapon-{assault_rifle,machine_gun,rocket_launcher,shotgun,sniper_rifle,submachine_gun}.png`(무기군).

## R1 — 보스의 약점 속성 팝업 (접수)

대상: 솔로 레이드·단일 덱 통계 "보스의 약점 속성" 팝업(`apps/desktop-ui/combat-conditions.js`).

1. 설명 문구 **삭제**: "니케 자신의 속성이나 보스 자신의 속성이 아닙니다. 속성 상성표는 쓰지 않고, 고른 약점과 같은 속성의 니케만 보너스를 받습니다."
   - 상단 경고 "보스의 약점 속성 — 이 속성 니케가 우월 코드 보너스를 받습니다."는 삭제 대상이 아니다(유지).
2. 속성 명칭에서 **영어 제외**: 작열 / 수냉 / 풍압 / 철갑 / 전격만 표시(현재 "작열 Fire" 등). 버튼 옆 현재 값 표시("약점 · 작열(Fire)")도 같은 기준으로 한국어만 쓰는 것으로 해석한다.

## R2 — 보스 거리 팝업의 무기군별 적정 사거리 표 (접수)

대상: "보스 거리" 팝업의 "무기군별 적정 사거리" 표와 하단 문구.

1. **무기군 칸**: 무기군 이미지(이미 있는 `weapon-*.png`) + 무기군 텍스트로 표시.
2. 열 제목의 **"(다수)" 삭제**: "적정 사거리(다수)" → "적정 사거리".
3. 예외 칸의 캐릭터: **이름은 한글**로(예: "Harran" → "하란"), **캐릭터 코드(#5042 등)는 UI에 노출하지 않는다.** (현재 표는 공개 roster 영어 이름과 코드를 그대로 보여준다.)
4. 하단 문구 **삭제**: "무기군 표는 참고용이며 판정은 캐릭터별 값을 씁니다(예외 캐릭터 반영). 원천 Database/raw/blabla_roledata.json · sha256:… · 실게임 검증 전".

관련 정리 후보(같은 배정에서 함께 처리할지 확인): 사거리 데이터·RL 0–0은 사용자 검증 완료(2026-09-29)이므로 화면의 "보너스 없음(확인 필요)"·"(양끝 포함 · 잠정)" 문구와 API `gameVerified=false`도 정리 대상이다. 경계값 양끝 포함 여부는 사용자 확인 대기.
