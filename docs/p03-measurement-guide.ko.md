# P03 틱 대미지 측정 조건

대상: **리타·블랑·누아르·앨리스·모더니아**. 사용자가 추후 제공할 실측을 위한 안내다. 이번 구현에서 새 실게임 대미지를 관측한 것은 아니다.

여기서 틱은 화면에 뜬 **피해 숫자 한 개**를 우선 의미한다. 평타 1발, SG 펠릿 1개, 추가타, 버스트 직격, 여러 숫자의 합계를 구별해야 한다. 지속 피해(DoT)만 뜻하는 용어로 사용하지 않는다.

## 이번 측정의 고정 대상

2026-09-08 사용자 제공 조건을 이번 실측의 기준으로 기록한다. 모든 시즌의 보스에 공통인 값으로 일반화하지 않는다.

| 항목 | 고정 값 |
|---|---|
| 콘텐츠·난이도 | 솔로 레이드 챌린지 보스 |
| 20억 대미지 전 방어력 | **30,925** |
| 20억 대미지 후 방어력 | **31,784** |

20억 전후는 해당 전투의 누적 대미지 기준으로 해석한다. 비교할 틱이 어느 구간에 있는지 누적 대미지나 영상 위치로 구분하며, 두 방어력 구간의 피해를 같은 조건으로 섞지 않는다. 정확히 20억인 경계의 포함 여부와 이를 넘기는 타격에 적용되는 방어력은 아직 확정하지 않는다. 우선 경계에서 충분히 떨어진 구간을 검산하고 전환 직전·직후 장면은 별도로 보존한다.

현재 평타 기준 실행은 요청당 고정 `EnemyDefense` 하나를 받는다. 구간별 검산에 위 값을 각각 사용하며, 누적 대미지에 따른 방어력 자동 전환은 아직 구현하지 않았다. 보스 이름/시즌, 공격 부위, 적 디버프는 실제 자료와 함께 식별한다.

## 먼저 필요한 공통 조건

| 조건 | 기록할 내용 |
|---|---|
| 측정 스펙 | 캐릭터·적용 레벨·스킬1/2/버스트 레벨, 측정 당시 계정 스냅샷. OL·큐브·소장품/애장품 변경 여부 |
| 편성 | 함께 출전한 캐릭터 전원과 자리, 수동 조작 캐릭터, 실제 버스트 시전자 |
| 적 | 콘텐츠/난이도·적 이름·레벨·페이즈, 본체/파츠/코어/저지 부위 중 어디인지, 적 버프·디버프 |
| 피해 종류 | 평타·펠릿·추가타·스킬/버스트 직격 구분, 숫자 하나인지 여러 숫자의 합계인지 |
| 명중 조건 | **크리, 코어, 적정 거리, 우월 상성, 파츠, 관통 중복 명중** 여부. 가능하면 실제 거리도 기록 |
| 차지 | 풀차지/부분 차지/톡톡이. 부분 차지면 확인 가능한 충전량. 자동/수동 구분 |
| 버스트 | **자기 버스트 효과 활성 여부**와 **팀 풀버스트 여부**를 별도 기록. 풀버스트 진입·종료 시점과 진입 횟수 |
| 활성 효과 | 버프/디버프 이름 또는 출처, 스택 수, 발동·만료 시점. 공격력 증가·공격 대미지 증가·적 받는 피해 증가 구분 |
| 체력·탄약 | 피해 발생 시 HP 비율, 현재/최대 탄 수, 재장전 직후인지, 명중 횟수 조건을 넘긴 직후인지 |
| 실제 결과 | 피해 숫자, 발생 시각 또는 영상 프레임, 측정일·게임 버전(알 수 있는 범위) |

계정 스펙은 저장된 스냅샷으로 확보하므로 항목을 전부 다시 타이핑할 필요는 없다. 장비나 육성이 바뀌었다면 동기화한 뒤 해당 측정과 묶으면 된다. 적 방어력처럼 알 수 없는 수치는 **미확인**으로 둔다. 0이라고 가정하지 않는다.

시간은 초 단위로 주어도 된다. 영상이 있다면 재생 시각과 원본 FPS를 함께 남긴다. 화면 숫자가 뜨는 시각과 내부 명중 시점은 다를 수 있어, 버프 경계에서는 앞뒤 장면이 도움이 된다. 카운터나 스택을 읽기 어렵다면 영상으로 대체해도 된다. CSV 작성은 필요 없다.

## 전투 후 로그·영상 제출

실제 전투를 마친 뒤 로그나 영상을 제공해도 된다. 현재 전용 로그 업로드·영상 자동 분석 기능이 구현되어 있다는 뜻은 아니며, 제공 자료에서 비교 가능한 관측을 정리해 검산한다.

- **상세 로그:** 시각·공격자·피해 종류·개별 피해·당시 조건이 있으면 틱과 발동 순서를 비교할 수 있다. 누적 대미지 또는 방어력 구간도 함께 식별한다. 없는 항목을 추측해서 채우지 않는다.
- **전투 결과 요약:** 팀/캐릭터별 총대미지만 있어도 전체 결과 비교에 사용할 수 있다. 다만 이 자료만으로 개별 틱의 공식·정수화·버프 순서를 확정할 수는 없다.
- **영상:** 피해 숫자, 전투 시간, 풀버스트 표시, 관련 버프/디버프, 누적 대미지 또는 전환을 식별할 화면 정보가 보이면 좋다. 전체 전투 영상도 가능하며, 보고 싶은 구간의 재생 시각을 함께 주면 된다. 짧은 클립이라면 필요한 버프 발동과 방어력 전환 전후가 포함되어야 한다. 읽히지 않는 숫자나 상태는 미확인으로 남긴다.

측정 당시 스냅샷과 덱·수동 조작·버스트 순서는 로그/영상에서 확인할 수 없는 경우에만 별도로 보충한다.

## 우선순위가 높은 측정 세트

1. **기준 평타:** 같은 적·같은 부위·같은 스펙에서 비크리/비코어 피해. 풀버스트 밖, 임시 버프가 없거나 정확히 파악된 구간. 상시 패시브와 OL을 억지로 끌 필요는 없다.
2. **조건 하나씩 비교:** 기준에서 크리만, 코어만, 적정 거리만, 풀버스트만 바꾼 피해. 실제로 하나만 바꾸기 어렵다면 함께 바뀐 효과를 모두 기록한다.
3. **공증 합산:** OL을 유지하고 스킬 공증 전/중/후를 비교한다. 스탯 원값과 스킬 공증이 합산되는지 검증한다. 풀버스트와 동시에 켜지는 버프를 공증 하나의 효과로 오인하지 않는다.
4. **경계 비교:** 버프 발동 직전/직후, 만료 직전/직후, 조건 충족 직전/직후의 피해. 같은 프레임의 처리 순서를 좁히는 데 사용한다.
5. **복합 조건:** 단일 조건이 맞은 뒤 크리+코어+풀버스트+여러 버프를 결합한다. 처음부터 팀 총딜 하나만으로 식을 보정하지 않는다.

같은 조건에서 구분되는 숫자별로 몇 번씩 확인해 주면 좋다. 여러 종류의 숫자를 평균내거나 가장 큰 숫자만 뽑지 않는다. 크리 여부가 불명확하면 값의 목록을 그대로 보존한다.

## 캐릭터별 추가 조건

| 캐릭터 | 우선 비교 | 함께 기록할 조건 |
|---|---|---|
| 리타 | 버스트 공증 전/중/후, 첫 번째와 이후 버스트 구간 | 자기 버스트 시전 횟수와 팀 풀버스트 진입 횟수를 구분. 장탄·크리 대미지·공증 관련 아이콘/중첩 상태 |
| 블랑 | 적 받는 피해 증가 전/중/후 | 실제 피해를 낸 캐릭터와 블랑의 버스트 시점, 적 디버프 아이콘. 누아르 동반 여부 및 체력 변화. 보호막 발동을 함께 볼 경우 120회 명중이 아닌 **120발 탄 소비**를 기준으로 관측 |
| 누아르 | HP 70% 조건 위/아래에서 본인·동료 평타, SG 한 발의 피해 숫자들 | **누아르 자신의 스탯 공격력 원값**과 수혜자 스펙 모두 필요. 시전자 기준 공증량에 누아르의 OL 공증은 영향을 주지 않음. 활성 공증은 각자의 평타 검산을 위해 별도 기록. 전체 펠릿 명중 여부·크리/코어 섞임·본인/블랑 버스트 구분 |
| 앨리스 | 평타 풀차지/비풀차지, 자기 버스트 전/중/후 | HP 80% 조건 위/아래, 관통으로 본체·파츠를 동시에 맞혔는지. 스킬1 대상 선정 당시 상위 공격력 2명과 버프 수혜 여부. 차지 대미지·차지 속도 버프 별도 기록 |
| 모더니아 | 평타 숫자와 추가타 숫자 각각, 스택 증가 전/후, 섬멸 모드 안/밖 | 명중 횟수/200회 경계, 크리 대미지·장탄 감소 스택, 명중률 버프와 조건부 공증, 풀버스트 여부와 본인 버스트 여부, 맞힌 적 수 |

HP 조건은 우선 문턱의 위·아래로 명확하게 나눈다. 정확히 70%/80%인 경계의 포함 여부는 별도 측정한다. 스탯 순위나 시전자 기준 효과가 언제 값을 읽는지도 측정 대상이며, 미확정인 상태에서 수치로 단정하지 않는다.

블랑의 불굴/최대 HP 버프를 실제로 받은 동료도 함께 식별하면 좋다. 최저 HP 선정의 **HP 비율 기준과 절대 남은 HP 기준**을 비교 중이므로, 당시 동료별 HP 비율과 스냅샷의 최대 HP를 함께 사용한다. 엄폐 회복 대상을 비교할 때도 가능하면 엄폐의 최대/현재 HP를 보존한다.

## 발사 시간도 제공할 경우

피해 숫자와 별도로 아래 정보가 있으면 무기 모델을 검증할 수 있다.

- 첫 발 시각, 관측 구간의 탄 소비 수, 마지막 발→재장전 시작→탄 보충→다음 발 시각.
- 앨리스: 자동/수동, 풀차지/톡톡이, 차속·재장전 버프, 연속 발사 시각.
- 모더니아: 예열 전/후, 사격을 멈춘 시간, 재장전 후 첫 발과 이후 간격.
- 누아르: 탄 보충이 몇 번 나뉘는지, 각 보충량·간격, 일부 장전 후 바로 쏘는지.

현재 보존한 C# 발사 모델과 upstream의 SG 장전/펠릿 해석·일부 모션 지연은 차이가 있다. 실제 발수와 시각으로 각각 구분하며 임의 총딜 보정 계수를 도입하지 않는다.

## 간단한 전달 형식

```text
캐릭터 / 스킬 레벨 / 사용한 스냅샷 또는 스펙 변경 사항:
편성 / 수동 조작 / 실제 버스트 시전자:
적 / 콘텐츠·난이도 / 부위·페이즈:
누적 대미지 또는 20억 전·후 / 적용 방어력:
피해 종류 / 숫자 한 개 또는 합계:
크리 / 코어 / 적정 거리 / 우월 상성 / 풀차지:
자기 버스트 활성 / 팀 풀버스트 / 시전·진입 횟수:
켜진 버프·적 디버프 / 스택 / HP 비율:
피해 숫자 / 발생 시각 또는 영상 위치:
미확인 조건:
```

기존 UI의 `단일 히트 검산`에서도 조건·실측 대미지·메모를 입력하고 JSON을 저장할 수 있다. 이 JSON에 없는 동료 스펙·체력·횟수 조건은 메모나 위 형식으로 보충한다. 실측 입력과 합성 검산은 별도로 보관한다.
