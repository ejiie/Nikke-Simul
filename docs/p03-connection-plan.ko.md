## 2. 구현된 부분과 연결이 필요한 부분

### 발사·탄 소비·명중·추가타

`SkillReplay.cs`는 발사 때 `Dispatch(3)`으로 탄 소비를, 평타 피해 처리 뒤 `Dispatch(31)`로 명중을 전달한다. SG는 한 발의 탄 소비와 여러 펠릿 명중을 구분한다. 무한탄창에서는 발사·명중이 발생해도 탄 소비 카운터를 올리지 않는다. 모더니아 추가타는 평타 명중 카운터로 재진입하지 않는다. 이 구분에 대한 기존 회귀 검사가 통과했다.

다만 전달 대상이 private `Battle` 내부의 스킬 리스너에 한정되어 있다. 외부 팀 제어기가 사용할 **발사·탄 소비·평타 명중·직접 스킬 타격·추가타의 명시적인 계약**은 없다. 피해량 로그를 보고 타격의 종류를 역추론하는 방식으로 게이지를 연결하면 중복 충전이나 누락 위험이 있다.

### 쿨다운

버스트 시전과 쿨다운 감소는 이미 `Actor.Ready`를 갱신한다. 내부 시각은 1/300초 정수이며, 1프레임은 5 tick, 1cs는 3 tick이다. 여러 작은 쿨감 항을 먼저 프레임으로 반올림하지 않는 회귀 검사도 통과했다.

현재 P04가 실행 도중 사용할 수 있는 준비 상태 조회·시전 요청 경계는 없다. 반환 결과는 종료 시점의 `CooldownReadyFrames`이고, `cooldown_change` 로그는 감소량만 담는다. 제어기가 별도의 쿨다운 복사본을 관리하도록 만들면 실제 스킬 상태와 어긋날 수 있다.

### 풀버스트

현재 `Cast()`는 모든 버스트 시전에서 `full_burst_duration_request`를 기록한다. 그러나 이 값은 상태 전이에 사용되지 않으며, `FullBurstWindows`가 진입·종료를 결정한다. 진입에서는 리타·누아르·앨리스·모더니아 트리거가, 종료에서는 블랑 트리거가 연결되어 있다.

모더니아의 공식 지속시간 1,500cs와 나머지 4인의 1,000cs는 자료에 있다. 이를 제어기에 전달할 때 **전체 지속시간인지 추가 연장량인지**, 어느 시전·사이클의 요청인지 구분해야 한다. 15초에 다시 5초를 더하거나 I·II의 요청으로 III의 지속시간을 덮어쓰면 안 된다. 무기 변경·무한탄창의 만료 시각과 풀버스트 종료 시각도 별개로 보존해야 한다.

### 게이지와 단계 원천

현행 catalog의 `weapon.burst`에는 `energyPerShot`, `targetEnergyPerShot`, `fullChargeEnergy`, `useBurstSkill`, `changeBurstStep`, `applyDelaySec`, `durationSec`가 보존되어 있다. 하지만 게이지 계산에는 아직 사용하지 않는다. `SkillLoadout`에는 지속시간만 있고, 단계·전환·적용 지연을 검증하는 팀 계약은 없다.

기존 `Nikke-Dmg-Simulator/Database/processed/burst_gauge_table.json`에는 출처를 ConfigBattleTable로 표시한 cap **1,000,000** 및 충전 관련 상수 자료가 있다. 현재 runtime catalog의 입력에는 이 파일이 포함되지 않는다. 상수의 존재와 실제 충전식을 검증한 것은 구분한다. 발사당 값·명중당 값·풀차지 값·공통 계수의 결합 방식은 원천 코드와 대조해 결정해야 한다.

기존 프로젝트의 `Events/BattleEvent.cs`는 참고 가능한 이벤트 분류를 제공하지만, 원본 `Combatant` 참조와 다목적 `IntValue`에 의존한다. 버스트 발행자는 원본 문서에서도 후속 T02다. 완성된 팀 사이클을 그대로 가져올 수 있는 상태로 판단하지 않는다.

### 로그와 검사 범위

이번 상세 실행은 **총 53,091개 중 20,000개**만 저장했으며 마지막 저장 프레임은 **4,185 = 69.75초**다. 계산 자체는 180초까지 정상 완료했다. 기존 API 감사는 특정 이벤트의 존재를 검사하지만, 전체 전투의 사이클별 전달 횟수·순서를 검사하지 않는다.

따라서 **게임 상태 변경 → 내부 이벤트 전달 → 선택적인 상세 로그 저장**의 경계를 마련해야 한다. 로그 비활성화·잘림이 제어기 동작을 바꾸면 안 된다. P04에 필요한 작은 사이클 요약은 대량의 히트 상세 로그와 별도로 수집한다.

## 3. 실행 순서

### P03-C1 — 입력과 출처 계약 확정

- 초기 5인의 단계·다음 단계·원천 적용 지연·지속시간·무기별 게이지 필드를 서로 대조하고 단위를 명시한다.
- 기존 게이지 표는 원천과 생성 경로를 확인한 뒤 hash를 고정해 runtime 입력에 포함한다. 두 원천이 다르면 선택한 근거와 차이를 남긴다.
- 원천 `burst_apply_delay=1cs`, 기존 프로젝트의 단계 지연 정책, III 시전 후 풀버스트 진입 지연을 서로 다른 항목으로 구분한다. 이번 감사의 1프레임 간격 시전표는 실제 게임 타이밍 근거로 쓰지 않는다.
- 모더니아 교체 `shot_id`의 게이지·히트 관련 필드 확보 여부를 조사한다. 누락된 교체 무기 정보를 기본 무기와 동일하다고 확정하지 않는다.
- 자료 연결 여부, 실행 지원 여부, 실측 확인 여부를 분리한다.

주요 대상: `prepare_runtime.py`, `RuntimeReplayService.Skills.cs`, `SkillDefinitions.cs`, P03 출처 manifest.

완료 조건: 필요한 값의 출처·단위·누락·상충을 모두 확인할 수 있고, P04 준비 상태에서 결손을 정상 값으로 취급하지 않는다.

### P03-C2 — 실행용 이벤트 계약 연결

- 별도 `CombatEvents.cs`에 최소한의 타입을 정의한다: 발사, 탄 소비, 평타 명중, 직접 스킬 타격, 추가타, 재장전 완료, 스킬 시전, 쿨다운 변경, 풀버스트 진입·종료 및 지속시간 요청.
- 이벤트에는 시각·안정적인 순서·원인 ID·캐릭터 ID·스킬/함수/무기 ID를 담는다. 타격에는 발사 ID·펠릿 식별·풀차지·크리·코어 등 필요한 정보를 명시한다.
- 발사와 탄 소비를 별도로 전달한다. 추가타의 평타 카운터 참여 여부와 게이지 충전 참여 여부도 분리한다. 추가타를 평타로 재분류하여 게이지를 연결하지 않는다.
- 현재 트리거 실행 위치와 함수 순서를 보존하며 공통 전달 지점을 만든다. 상세 로그를 제어기의 입력으로 사용하지 않는다.

주요 대상: `SkillReplay.cs`, `SkillDefinitions.cs`, 신규 이벤트 계약. `SkillFiringModel`은 실제 반환 정보가 부족한 범위에서만 보완한다.

완료 조건: 테스트용 소비자가 상세 기록 off/상한 도달 상태에서도 모든 관련 이벤트를 정확히 한 번 받는다. 기존 발수·탄 소비·피해 합계가 유지된다.

### P03-C3 — 쿨다운 조회·시전 경계 연결

- 기존 정수 deadline을 유일한 쿨다운 상태로 유지한다. 준비 여부 조회와 시전 요청을 같은 상태에서 처리한다.
- 쿨다운 변경 이벤트에 요청 감소량·실제 적용량·변경 전/후 deadline을 담는다. 이미 준비된 스킬의 감소량 0도 구별할 수 있게 한다.
- 미준비 시전 요청은 명시적인 결과로 반환하고, 준비 상태를 잘못 앞당기지 않는다. 기존 잘못된 지정 시전 요청을 거부하는 API 동작도 보존한다.
- 같은 프레임의 쿨감과 시전 판정을 어느 순서로 처리하는지 고정한다. 단일 tick 상태에서 판단하고, 프레임 표시는 경계에서만 계산한다.

주요 대상: `SkillReplay.cs`, 신규 `SkillBattleSession` 또는 동등한 작은 명령·조회 인터페이스.

완료 조건: 리타 쿨감·블랑 풀버스트 종료 쿨감 직후 제어기 조회가 실제 런타임과 일치하며 쿨다운 복사본이 없다.

### P03-C4 — 풀버스트 제어 경계 연결

- 지정 시간표와 향후 P04 제어기가 공통 진입·종료 함수를 사용하도록 정리한다. 현재 지정 실행 경로는 검산용으로 유지한다.
- 지속시간 요청에 시전자·버스트 단계·시전 원인·전체 지속시간의 의미를 명시한다. 모더니아 15초를 연장량 15초로 해석하지 않는다.
- 상태를 변경한 뒤 해당 스킬 트리거를 한 번씩 전달한다. 중복 진입·중복 종료는 상태를 다시 변경하거나 트리거를 재실행하지 않도록 처리한다.
- 풀버스트 구간은 기존 `[시작, 종료)`를 유지한다. 종료 프레임 타격, 같은 프레임의 종료/새 진입, 버프 만료/틱/시전 순서를 검증한다.
- 무기 모드 만료와 풀버스트 종료를 합치지 않는다. 실제 지연 정책은 P04의 버전 있는 입력으로 연결할 수 있게 준비한다.

주요 대상: `SkillReplay.cs`, 실행 세션 경계, 지속시간 요청 계약.

완료 조건: 테스트용 제어기가 진입·종료를 요청하면 리타·블랑·누아르·앨리스·모더니아 효과가 지정 실행 경로와 동일하게 반응한다. 자동 게이지/시전자 선택은 아직 구현하지 않는다.

| 시간 경계 | 준비 직전/정확히 준비된 프레임, 작은 쿨감 중첩, 같은 프레임 종료·시전·진입·발사 순서 |
| 기록 방식 | 상세 on/off/극소 상한에서도 이벤트 소비 결과·상태·집계 일치 |

합성 fixture는 계약 검증용으로, 공식 5인 자료를 사용하는 검사는 데이터와 실행 연결 검증용으로 구분한다. 정해진 조건에서 재현 가능한 검사를 사용하며, 이번 범위에 고정 시드 API를 추가하지 않는다.

### P03-C6 — 180초 인계 검증과 출처 기록

- 5인의 기존 지정 시전 시나리오와 테스트용 제어 경로를 같은 조건으로 비교한다. 마지막 프레임까지 이벤트 전달·쿨다운·풀버스트 요약을 확인한다.
- 정수화 3후보 각각에 대해 변경 전/후 발수·탄 소비·직접 피해 effect 합계를 비교한다. 순수 연결 변경으로 피해가 달라지면 원인을 조사한다.
- 모더니아를 시전하는 구간도 별도 짧은 trace로 검사하여 전체 상세 로그 상한 때문에 빠지지 않게 한다.
- 저장·재조회, 실제 스킬 레벨 보존, 입력·엔진·자료 버전과 미지원 표시를 다시 확인한다. 새 계약 버전을 기록하고 기존 저장 기록 읽기를 보존한다.
- 기능별로 재사용/변경/신규 작성 출처와 검증 결과를 정리한다. `connectionReady`와 `gameVerified`는 별도 상태로 관리한다.

완료 조건: **P04가 상세 로그를 해석하지 않고 발사·타격을 받고, 최신 쿨다운으로 시전하며, 풀버스트 진입·종료와 지속시간을 전달할 수 있다.** 이 상태를 P03 연결 준비 완료로 선언한다. 실전 대미지 정확도나 자동 사이클 완성을 의미하지 않는다.
