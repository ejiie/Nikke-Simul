## 사고 수준 (reasoning effort)

사용자 승인(2026-09-29). **모든 지시서에 담당별 사고 수준을 명시한다.**

| 역할 | 기본 | 올리는 경우 | 이유 |
|---|---|---|---|
| sonnet-5.5 구현 | **high** | 엔진·수치·저장 호환 → **xhigh** | 이 프로젝트의 결함은 대부분 의미 결함(누락 값 0 채움, 지표 전체 숨김, 조건 재해석)이다 |
| sonnet-5.5 구현(UI 문구·배치만) | **medium** | — | 문구 삭제·레이아웃 변경 수준 |
| astra-6 리뷰 | **medium** | 재리뷰도 medium | 체크리스트 대조. low는 4·5번(재해석·추정 채움)처럼 의미를 읽어야 하는 항목을 놓칠 위험 |
| 독립 QA | **high** | 수치 산술·경계 검증 → **xhigh** | 실제 결함을 찾아온 단계. 독립 기준 설계·손상 주입에 사고가 필요 |

운영 규칙:

- **반려 후 다음 구현 시도는 한 단계 올린다**(medium → high → xhigh).
- 작업 크기 기준: 지시서 항목 3개 이하·한 파일 안이면 medium, 여러 모듈이나 계약(wire) 변경이 있으면 high.
- 검수 세션 사용 한도가 낮으면 QA 수준은 유지하고 부하 측정(Q-CPU-10K 등)을 보류한다.

예: UI 문구·표 수정 = 구현 medium / 리뷰 medium / QA high. 엔진 규칙·수치 변경 = 구현 xhigh / 리뷰 medium / QA xhigh.

## 리뷰 차단 기준 (하나라도 위반하면 반려)

1. **범위·소유:** 지시서의 소유 경로 밖 파일, 다른 담당·QA 파일을 수정하지 않았다.
2. **보존 규칙:** 원본 `data/local`의 계정 DB(`accounts.db`)·세션·캐시·presentation·EXE·5180/5181에 접근·변경하지 않았고(**예외: 공개 게임 데이터 표 — `game-catalog.json`, `calculation/*`, `runtime/*` — 의 읽기 전용 사용은 허용. 전후 hash를 기록하고, 복사본은 자기 worktree artifacts 안에 두거나 작업 후 삭제한다.** 2026-10-02 Director 판단, 기존 H-SRC·I-BE·QA 관행과 같음), `package-lock.json`을 커밋하지 않았고, push·배포·새 워커가 없다.
3. **요구 대조:** 지시서의 항목 번호별로 구현 여부를 체크리스트로 확인한다. 누락 항목이나 요구하지 않은 동작 추가가 없다.
4. **조용한 재해석 없음:** 이전 저장본·이전 조건·이전 정책을 새 의미로 바꾸지 않았고, 이전 결과 재현 경로가 남아 있다.
5. **추정 채움 없음:** 누락 값을 0·기본값으로 채우거나, 예외를 삼키거나, 모르는 값을 추정하지 않는다(예: 사거리 누락 0 채움 결함 F-COND-Q-1).
6. **테스트 증거:** 새 동작에 테스트가 있고 보고서에 실행 결과가 있다. 리뷰어가 빌드·테스트를 **1회** 실행해 보고 수치와 일치하는지 확인한다(추가 실험 없음).
7. **버전·fingerprint:** 계산 결과가 바뀌는 변경이면 규칙 버전이 올라가고 캐시·fingerprint 입력에 새 조건이 포함된다.

## 비차단 (기록만, 통과)

이름·스타일·리팩터링 제안·성능 아이디어·문구 다듬기. 반려 사유로 쓰지 않고 리뷰 결과에 따로 모아 둔다.

## 리뷰어가 하지 않는 것

- 코드를 직접 수정하지 않는다.
- 새 실험, 실제 API·브라우저 종단 검증, 대량 실행을 하지 않는다(QA 몫).
- 지시서 범위 밖 개선을 요구하지 않는다.

## 리뷰 결과 형식

- `통과` 또는 `반려`.
- 반려는 결함마다 한 줄: `파일:줄 — 위반 항목 번호 — 이유`.
- 비차단 의견은 별도 목록.
- 빌드·테스트 1회 실행 결과(통과 수)를 적는다.
