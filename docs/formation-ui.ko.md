# 솔로 레이드 편성 UI

## 동작

- 저장 이력이 없는 계정은 `+ | + | + | + | +`로 시작한다.
- 솔로 레이드의 어느 칸을 눌러도 편성 선택 화면으로 이동한다.
- 상단에는 편성 5칸, 하단에는 기존 니케 도감의 검색·필터·전투력 정렬·카드를 표시한다.
- 보유 니케를 짧게 누르면 왼쪽의 첫 빈칸에 추가한다. 중복과 6번째 멤버는 추가하지 않는다.
- 선택 화면의 채워진 칸을 누르면 그 칸만 비운다. 나머지 멤버의 위치는 유지한다.
- 카드를 1초 이상 누르면 상세로 이동한다. 해제 시 추가 선택하지 않는다. 이동·스크롤·포인터 취소·창 포커스 이탈은 길게 누르기를 취소한다. 키보드는 Alt+Enter로 상세를 열 수 있다.
- 상세의 `<`는 진입한 도감 또는 편성 선택 화면으로 돌아온다. 검색·필터·스크롤 위치 및 선택 중 편성을 유지한다.
- `편성 저장`은 계정별 편성을 저장하고 솔로 레이드로 돌아간다. `취소`는 저장된 편성으로 돌아간다. 저장 실패 시 선택 중인 편성을 유지하고 오류를 표시한다.
- 초상화, 무기군, 버스트 단계, 속성, 별 3개와 코어 강화(1 이상)를 슬롯에 표시한다. 무기군은 흰색 육각형, 버스트 단계는 어두운 육각형과 흰색 테두리 안에 기존 공식 아이콘을 배치한다. 버스트 이미지는 육각형을 기준으로 절대 중앙 배치하고 contain의 그림 정렬도 중앙으로 고정한다. 편성에서는 너비 52%·높이 48%, 도감에서는 너비 60%·높이 52%의 상자 안에 표시한다. 도감의 기존 grid 정렬로 숫자 폭이 재축소되지 않도록 처리했다. 니케 관리/편성 선택 도감 카드의 무기군·버스트도 검은 육각형 안에 표시한다.

## 저장과 기존 기능 연결

`GET/PUT /api/accounts/{id}/formation`과 기존 SQLite의 `solo_formations` 테이블을 사용한다. 5칸의 캐릭터 ID 또는 null, 계정 ID, 저장 시각을 보존한다. 계정 스펙 스냅샷과 분리하므로 스펙 편집·재수집·앱 재실행으로 초기화하지 않는다. API에서도 5칸 형식, 중복, 해당 계정의 보유 여부를 검사한다. 빈 편성도 저장할 수 있다.

검산 요청은 저장된 편성의 왼쪽부터 빈칸을 제외한 순서로 생성한다. 편성에는 모든 보유 니케를 선택할 수 있지만, 현재 스킬 검산 엔진의 지원 범위는 기존의 리타·블랑·누아르·앨리스·모더니아다. 지원 대상 안내를 검산 화면에 표시한다. 이번 변경에서 계산식·스탯·스킬 효과·자동 버스트 엔진은 변경하지 않았다.

## 가져온 기능과 신규 구현

| 구분 | 출처 |
| --- | --- |
| 니케 도감, 카드, 필터, 전투력 정렬 | 기존 `cards.js`, `index.html`, Local Lab 기반 `editor.css` 재사용 |
| 니케 상세와 스펙 편집 | 기존 `local-lab-adapter.js` 재사용 |
| 초상화·무기군·버스트·속성·별·코어 이미지 | 기존 블라블라 및 사용자 제공 ZIP 캐시 재사용 |
| 5칸 편성, 저장·취소·해제, 계정별 보존 | 신규 `formation.js`, Contracts/Storage/API |
| 짧게 누르기/길게 누르기와 취소 처리 | 신규 `card-gesture.js` |
| 진입 경로에 따른 상세 뒤로 가기 | `app.js`의 화면 문맥과 스크롤 복원 |

## 검증

- `Nikke.Sync.Tests`: 53개 통과. 편성 저장·재시작·스냅샷 갱신·계정 분리 및 잘못된 저장 차단 포함.
- `tools/data-pipeline/tests/check_formation_ui.py`: 실제 데이터의 임시 복사본과 별도 백엔드(5187)에서 선택/해제/중복/정원/미보유/길게 누르기/취소/뒤로 가기/저장/복원/계정 전환/저장 실패를 검증한다. 실계정 데이터는 변경하지 않는다.
- 500·850·1500px에서 슬롯 이미지와 가로 넘침 확인.
- 실행 파일이 사용하는 백엔드에 새 빌드를 반영하고 health 응답을 확인했다. 네이티브 숨김 창 smoke는 완료되지 않아 종료했다. UI 검증은 동일 `/editor` 화면을 Edge/Playwright에서 수행했다.
